## 📋 نظرة عامة

مشروع **ETL + Analysis + Visualization** يستخرج بيانات مبيعات AdventureWorks من MariaDB، ينظّفها ويفحص جودتها، يبني Star Schema، ثم يحلّلها ويعرضها في لوحة Streamlit تفاعلية.

| البند | القيمة |
|---|---|
| عدد الصفوف | 121,317 (بند بيع) |
| الأعمدة | 23 |
| الفترة | 2011-05-30 → 2014-06-29 |
| إجمالي المبيعات | 109.85M |
| هامش الربح الكلي | 8.53% |
| المصدر | MariaDB (AdventureWorks 2019) |

## 🔍 الاكتشاف الأهم: القناة وليس المنطقة

التحليل الأولي أشار إلى أن ثلاث مناطق (2 و3 و5) خاسرة، فبدا الأمر "مشكلة تسعير إقليمي". لكن فصل البيانات حسب **قناة البيع** كشف تفسيرًا مختلفًا.

### 1) الفرق بين القناتين

| القناة | هامش الربح |
|---|---|
| مندوبين (B2B) | **≈ −2.9%** |
| أونلاين (B2C) | **≈ +39.8%** |

### 2) داخل كل قناة، المناطق متشابهة

- **المندوبون (B2B):** خاسرون في **كل** المناطق العشر (من −0.9% إلى −6.8%).
- **أونلاين (B2C):** هامش بين **39.1% و42.4%** في كل منطقة.

أي أن الفروق الظاهرة بين المناطق كانت **انعكاسًا لاختلاف مزيج القنوات** في كل منطقة.

### 3) كلما زادت حصة المندوبين انخفض هامش المنطقة

| المنطقة | حصة بنود المندوبين | هامش المنطقة |
|:---:|:---:|:---:|
| 9 | 11.4% | 32.2% |
| 8 | 25.3% | 21.2% |
| 10 | 33.8% | 16.1% |
| 7 | 38.8% | 12.3% |
| 1 | 46.7% | 8.5% |
| 4 | 52.2% | 6.5% |
| 6 | 60.0% | 2.5% |
| 5 | 99.3% | −1.9% |
| 2 | 99.5% | −3.9% |
| 3 | 99.7% | −1.8% |

> الحصة محسوبة على **عدد بنود البيع** وليس على قيمة المبيعات.

### 4) هل المشكلة في منتج معيّن؟

لا. أكبر منتج خاسر مسؤول عن **5.1%** فقط من إجمالي الخسائر، فالخسارة موزّعة على منتجات كثيرة.

### لماذا هذا مهم؟

هذا مثال على **تأثير مزيج القناة (Confounding)**: متغيّر خفي (قناة البيع) يرتبط بالمنطقة وبالربحية معًا، فيُنتج علاقة ظاهرية مضللة بين المنطقة والربحية عند تجميع البيانات.

**الدرس:** التجميع قد يخفي السبب الحقيقي، والتفصيل يكشفه. افصل البيانات حسب القناة قبل استنتاج أي علاقة بين المنطقة والأداء.

## ⚠️ ملاحظات منهجية وحدود التحليل

- **حساب الربح:** `Profit = LineTotal − OrderQty × StandardCost`. قيمة `LineTotal` بعد الخصم.
- **التكلفة ثابتة:** `StandardCost` هي التكلفة المعيارية الحالية للمنتج وليست تكلفته وقت البيع (جدول `production_productcosthistory` غير مستخدم). لذلك الهوامش الصغيرة السالبة لقناة المندوبين (−1% إلى −7%) تعني "قرابة التعادل أو خسارة طفيفة" أكثر مما تعني خسارة حاسمة.
- **طبيعة البيانات:** AdventureWorks قاعدة بيانات تجريبية، والأرجح أن سعر الجملة فيها قريب من التكلفة بحكم التصميم. فالنتيجة صحيحة لهذه البيانات، ولا يجوز تعميمها على شركة حقيقية دون تحقق.
- **الخصومات:** البنود المخفّضة فعليًا 2.7% فقط (`UnitPriceDiscount > 0`)، فالخصم لا يفسّر الخسائر. تصنيف "خاسر" يعني `Profit < 0` فقط.
- **سنوات ناقصة:** 2011 تبدأ من 30 مايو و2014 تنتهي في 29 يونيو، فلا تُقارَن مبيعات السنوات الإجمالية مباشرة.
- **تحليل المواسم:** لم يُضبط تأثير السنوات، فلا تُعتمد استنتاجات موسمية دون مقارنة داخل السنة نفسها.

## 🚀 التشغيل

### 1) تثبيت المكتبات

```bash
pip install -r requirements.txt
```

### 2) تشغيل ETL (اختياري)

يحتاج قاعدة AdventureWorks تعمل على MariaDB/MySQL.

```bash
cp .env.example .env     # ثم عدّل قيم الاتصال
```

افتح `ETL.ipynb` ثم `Kernel → Restart & Run All`. بدون هذه الخطوة يمكنك استخدام `output/adventureworks.csv` الجاهز.

### 3) تشغيل التحليل

افتح `analysis.ipynb` (يقرأ من `output/adventureworks.csv` ويعمل في ثوانٍ).

### 4) تشغيل اللوحة

```bash
streamlit run dashboard.py
```

ثم افتح `http://localhost:8501`.

## 📊 ما تعرضه اللوحة

- **4 تبويبات:** الملخص التنفيذي، المنتجات والفئات، المناطق، التوصيات.
- **8 مؤشرات (KPIs):** المبيعات، الربح، الهامش، الطلبات، الكمية، العملاء، متوسط الطلب، نسبة البنود الرابحة.
- **الفلاتر:** السنة، الفئة، المنطقة، **قناة البيع** (أونلاين / مندوبين)، ونوع الصفوف (رابحة / خاسرة / مخفضة).
- **مقارنة القنوات** ورؤى تلقائية.
- **تنزيل** البيانات المفلترة بصيغة CSV.

## ✅ التوصيات

1. **مراجعة سياسة تسعير المندوبين (B2B):** سعر الجملة الحالي قريب من التكلفة المعيارية، فيلزم حدّ أدنى لسعر البيع.
2. **التوسع في الأونلاين بحذر:** هامشه مرتفع، لكن بنوده صغيرة (قطعة واحدة غالبًا)، فيلزم اختبار قابلية التوسع.
3. **دراسة نموذج المنطقة 9:** أعلى هامش (32.2%) وأقل اعتماد على المندوبين.
4. **تحليل القناة دائمًا:** لا تُقارَن المناطق دون فصل القناة.
